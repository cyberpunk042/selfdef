## Problem

Sandboxed agent code (running in a MS032 sandbox-tier VM or
container) needs SOME network egress for legitimate work
(pull packages from PyPI, fetch docs, drive an authenticated browser
session). Giving it "internet" is too coarse:

1. **Implicit egress** — a sandbox process could reach any host;
   exfiltration goes silent.
2. **No profile discipline** — "agent that reads docs" gets the
   same authority as "agent that authenticates a browser session";
   blast-radius on credential compromise is huge.
3. **No deny-by-default** — most agent work fits one of 3 narrow
   profiles; giving the default the maximum width inverts least-
   privilege.
4. **No cross-cycle binding** — without typed profiles, the
   authority-ring graph (MS039) can't compose with egress.

## Goals

1. 5-profile egress ladder per E0382 dump 3596-3604:

   | profile               | bits      | scope                              |
   |-----------------------|-----------|------------------------------------|
   | `offline`             | `00000000`| no egress                          |
   | `package-registries`  | `00000001`| npm / PyPI / crates.io / …         |
   | `docs-only`           | `00000011`| + read-only documentation hosts    |
   | `arbitrary-web`       | `00000111`| + general egress                   |
   | `authenticated-browser`| `00001111`| + logged-in session websites      |

   Bit-packed so a single u8 carries the profile + bits 16..23 of
   the capability_word encode the profile per F04526.
2. `NetworkGrant {profile, allowed_hosts:BTreeSet, allowed_ipv4:Vec<Cidr>}`
   — typed allow-list per grant.
3. `validate()` — refuses empty hosts, empty CIDRs, malformed input.
4. `permits_host(host)` + `permits_ipv4(ip)` predicates — call sites
   check the grant before opening a connection.
5. Cross-cycle binding per F04527: Tier A=offline, Tier B=package-
   registries, Tier C=docs+arbitrary, Tier D=authenticated-browser.
6. Cross-cycle binding per F04528: composes with MS039 authority-
   graded egress (Ring 0-4).

## Non-goals

- This SDD does NOT cover INBOUND policy (firewall rules for
  selfdef-served ports); that's `selfdef-network-cidr-allowlist`
  on the `/v1/*` API surface, separate concern.
- It does NOT cover TLS-inspection (that's the polarproxy module).
- It does NOT cover DNS rewriting (separate operator concern).

## Alternative designs considered

**Alt 1 (rejected): single `allow_external_egress: bool` config
key.** Trivially small. Rejected — collapses 5 distinct profiles
into one boolean; doesn't model the docs-only / package-registries
distinction the operator cares about.

**Alt 2 (rejected): per-process iptables rules generated by the
daemon.** Strong isolation but couples selfdef to a host firewall
implementation. Rejected — sovereign-os runs on multiple host stacks
(systemd-resolved, nftables, NetworkManager) + per-process rules
require netns + the daemon would own restart-recovery for thousands
of rules.

**Alt 3 (CHOSEN): typed `NetworkProfile` enum + `NetworkGrant`
allow-lists + caller-side predicate checks.** Profiles compose into
MS039 authority rings. Predicate checks live next to each call site
that opens a connection. iptables / nftables enforcement happens at
the host firewall layer informed by selfdef's typed state via the
typed mirror.

## Recommended design

### Types (shipped)

```rust
pub enum NetworkProfile {
    Offline,
    PackageRegistries,
    DocsOnly,
    ArbitraryWeb,
    AuthenticatedBrowser,
}

impl NetworkProfile {
    pub fn policy_bits(self) -> u8;        // 0x00 .. 0x0F
    pub fn from_policy_bits(b: u8) -> Option<Self>;
    pub fn allows_egress(self) -> bool;    // false for Offline
}

pub enum AllowEntry { Host(String), Ipv4Cidr([u8;4], u8) }

pub struct NetworkGrant {
    pub profile: NetworkProfile,
    pub allowed_hosts: BTreeSet<String>,
    pub allowed_ipv4: Vec<([u8;4], u8)>,
}

impl NetworkGrant {
    pub fn validate(&self) -> Result<(), NetworkError>;
    pub fn permits_host(&self, host: &str) -> bool;
    pub fn permits_ipv4(&self, ip: [u8;4]) -> bool;
}
```

### Caller contract

Every egress-attempting call site MUST:

1. Resolve the active `NetworkProfile` from the operator-issued
   capability token (SDD-044 scope check first).
2. Construct the `NetworkGrant` from the operator's `[network]`
   config block + per-task `allowed_hosts` + `allowed_ipv4`.
3. Call `grant.validate()` — refuse-to-proceed on Err.
4. Before opening the connection: call `grant.permits_host(target)`
   OR `grant.permits_ipv4(target)`; refuse on `false`.
5. Audit the egress decision via SDD-043 CommitEnvelope
   (commit_type = `ToolSideEffect`).
