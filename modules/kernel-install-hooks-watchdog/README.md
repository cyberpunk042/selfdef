# kernel-install-hooks-watchdog

Boot + daily delta of the kernel-package install-hook dirs against
a learned baseline, plus an ownership + suspicious-pattern scan.
Catches a hook that runs as root on every kernel package
transaction. MITRE **T1542** / **T1546**.

## Why this matters

dpkg's kernel maintainer scripts (and systemd `kernel-install`) run
**every executable** in these dirs **as root** on each kernel
package transaction — install, upgrade, or remove:

- `/etc/kernel/postinst.d/*` — post-install (update-grub,
  update-initramfs, bootloader regen live here)
- `/etc/kernel/postrm.d/*` — post-remove
- `/etc/kernel/preinst.d/*` — pre-install
- `/etc/kernel/prerm.d/*` — pre-remove
- `/etc/kernel/install.d/*` — systemd `kernel-install` plugins
- `/etc/kernel/header_postinst.d/*` — header package post-install

Because these scripts already legitimately regenerate the initramfs
and bootloader, an attacker who drops a hook here gets **root
execution on the next kernel update** with a natural place to plant
into the initramfs or bootloader — pre-OS boot persistence that
survives a reinstall of userspace.

This is distinct from:

- the **runtime `kernel-*` modules** (cmdline / lockdown / modules /
  sysrq / yama) — those watch live kernel *parameters*, not the
  package hook dirs.
- **apt-hooks-watchdog** — apt's own `DPkg::Pre-Invoke` /
  `Post-Invoke`; these are the kernel-package maintainer-script hook
  dirs, a different dispatcher.

## Profiles

| Profile | Effect |
|---|---|
| `report` (default) | log delta; exit 0 |
| `enforce` | exit 1 on any kernel-hook change → systemd unit failed → notifier engine |

## Severity ladder

| Condition | Severity | Event |
|---|---|---|
| First scan | `ok` | `baseline_initial` |
| No kernel hook dirs present | `ok` | `no_kernel_hooks` |
| No delta | `ok` | `kernel_hooks_intact` |
| A hook added / changed / removed | `warn` | `kernel_hooks_changed` |
| A hook world-writable / non-root-owned, OR containing a suspicious command-injection pattern | `alert` | `kernel_hooks_suspicious` |

## What's recorded

- `file:<path>:<sha12>` — hash of each hook.
- `own:<path>:<owner:mode>` — owner + mode (symlinks dereferenced
  with `stat -L`).
- `susp:<path>:<pattern>` — a high-risk exec pattern (`curl|sh`,
  `/dev/tcp`, `bash -i`, `base64 -d`, `python -c`, `perl -e`,
  `eval $(...)`, tmp/shm/home execution, …); comment-only lines
  stripped first.

## Cadence

`OnBootSec=49min` + `OnCalendar=*-*-* 10:10:00` — extends the
staggered ladder after dhclient-hooks (10:05). An injected hook
fires on the next kernel package transaction, so the daily catch
bounds dwell time before the next update; the boot catch confirms
the hook set after a restart.

## MITRE coverage

- **T1542** Pre-OS Boot — the hook can plant into the initramfs /
  bootloader regenerated by these very scripts.
- **T1546** Event Triggered Execution — the kernel package
  transaction is the trigger.
- **T1059.004** — the hook is shell execution run as root.

## Operator workflow

```bash
journalctl -t selfdef-kernel-hooks -n 1 --no-pager
journalctl -t selfdef-kernel-hooks-detail --since "1 day ago"

# Inventory
ls -la /etc/kernel/postinst.d/ /etc/kernel/postrm.d/ \
       /etc/kernel/install.d/ 2>/dev/null

# Investigate a suspicious alert, then re-baseline:
sudo $EDITOR /etc/kernel/postinst.d/<hook>
sudo rm /var/lib/selfdef/kernel-install-hooks-baseline.tsv
sudo systemctl start selfdef-kernel-hooks.service
```

## Caveats

- **Distro packages populate these dirs** (initramfs-tools, grub,
  zz-update-grub, dkms, systemd-boot); a new root-owned hook with no
  suspicious pattern fires `warn` (re-baseline). The
  writable/non-root/injection tiers are the high-confidence alert.
- **Minimal/container images** with no kernel package management
  often have empty/absent dirs → `no_kernel_hooks` no-op.
- **Daily+boot cadence** misses a drop-update-revert inside the
  window; an audit-rules watch on the hook dirs' writes is the
  real-time complement. The initramfs build *content* itself is a
  separate (future) surface from these hook *dirs*.

## Coexistence

- **kernel-cmdline-watchdog / kernel-lockdown / kernel-module-watchdog**:
  runtime kernel params; this is the kernel-package install-hook
  surface.
- **apt-hooks-watchdog / dnf-plugins-watchdog**: package-manager
  invoke hooks; this is the kernel-specific maintainer-script hook
  dirs that those transactions drive.
- **aide-bridge / integrity-sentinel**: byte-level integrity on the
  hooks; this adds the ownership + injection-pattern view.
